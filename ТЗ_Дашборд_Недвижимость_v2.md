## 0. Контекст и цель

Публичный информационный сайт с интерактивными дашбордами по рынку жилой
недвижимости России — аналог frankrg.com/data-hub. Более 110 показателей,
горизонт 2011–2026: ввод жилья, цены, спрос, ипотека, предложение.

## 2. База данных PostgreSQL

### 2.1 Схема (реализована в migration/001_init.sql)

```sql
CREATE TABLE sources (
    id SERIAL PRIMARY KEY, code VARCHAR(50) UNIQUE NOT NULL,
    name TEXT NOT NULL, base_url TEXT, update_freq VARCHAR(50), notes TEXT
);

CREATE TABLE categories (
    id SERIAL PRIMARY KEY, code VARCHAR(50) UNIQUE NOT NULL,
    name TEXT NOT NULL, sort_order INT DEFAULT 0
);

CREATE TABLE indicators (
    id SERIAL PRIMARY KEY, code VARCHAR(100) UNIQUE NOT NULL,
    category_id INT REFERENCES categories(id),
    source_id   INT REFERENCES sources(id),
    name TEXT NOT NULL, unit TEXT,
    periodicity VARCHAR(20),   -- 'monthly' | 'quarterly' | 'annual'
    period_type VARCHAR(20),   -- 'period' | 'point_in_time'
    geo_level   VARCHAR(20) DEFAULT 'russia',
    description TEXT, source_url TEXT, last_updated TIMESTAMPTZ,
    is_public BOOLEAN DEFAULT TRUE,
    chart_type VARCHAR(20) DEFAULT 'line',  -- 'line' | 'bar'
    sort_order INT DEFAULT 0
);

-- Хранятся ТОЛЬКО абсолютные значения. Динамика считается в materialized view.
CREATE TABLE data_points (
    id BIGSERIAL PRIMARY KEY,
    indicator_id INT REFERENCES indicators(id) ON DELETE CASCADE,
    period_date DATE NOT NULL,    -- первый день периода
    period_label VARCHAR(50),     -- 'Январь 2024', 'Q1 2024', '2024'
    value NUMERIC(20,4),          -- NULL = данных нет (не 0!)
    is_preliminary BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    UNIQUE(indicator_id, period_date)
);

-- YoY, MoM, YTD рассчитываются автоматически
CREATE MATERIALIZED VIEW data_points_with_dynamics AS
SELECT dp.*, 
    LAG(dp.value) OVER (PARTITION BY dp.indicator_id, EXTRACT(MONTH FROM dp.period_date) ORDER BY dp.period_date) AS value_prev_year,
    <yoy_change через CASE/LAG>,
    LAG(dp.value) OVER (PARTITION BY dp.indicator_id ORDER BY dp.period_date) AS value_prev_period,
    SUM(dp.value) OVER (PARTITION BY dp.indicator_id, EXTRACT(YEAR FROM dp.period_date) ORDER BY dp.period_date ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS value_ytd
FROM data_points dp;

CREATE UNIQUE INDEX ON data_points_with_dynamics(indicator_id, period_date);

CREATE TABLE update_jobs (
    id SERIAL PRIMARY KEY, source_id INT REFERENCES sources(id),
    started_at TIMESTAMPTZ DEFAULT NOW(), finished_at TIMESTAMPTZ,
    status VARCHAR(20), rows_upserted INT, error_message TEXT
);
```

После каждого обновления данных выполнять:
```sql
REFRESH MATERIALIZED VIEW CONCURRENTLY data_points_with_dynamics;
```

## 3. Миграция данных (реализована)

### 3.1 Первичная миграция из Excel

```bash
python migration/excel_to_db.py migration/data/file.xlsx
```

Файл обрабатывает 4 структурных паттерна:
- **Паттерн A** — данные НА ДАТУ (datetime в первом столбце): листы 3.x, 6.19–6.27
- **Паттерн B-simple** — данные ЗА ПЕРИОД, один столбец на год: листы 4.x, 5.x, 6.28–6.87
- **Паттерн B-cum** — данные ЗА ПЕРИОД с накопительным итогом: листы 2.1–2.8, 5.1–5.2, 6.1–6.18, 6.70–6.87. Берём только подстолбец «в том числе месяц».
- **Паттерн C** — годовые данные, строка «Итого»: листы 1.x, 2.9–2.13, 5.10–5.15

### 4.3 Ключевые детали реализации

**YoY/MoM для процентных показателей (unit='%'):**
Возвращается абсолютная разность в п.п., а не относительная %:
```python
CASE WHEN i.unit = '%' THEN d.value - d.value_prev_year ELSE (d.value - d.value_prev_year)/ABS(d.value_prev_year)*100 END AS yoy_change_pct
```

**export_multi_xlsx** генерирует два листа:
- «Данные» — все периоды, все коды в столбцах (значение + г/г + м/м)
- «Годовые» — накопленный итог за год (только для period_type='period')

## 8. DevOps и инфраструктура

### 8.1 Локальная разработка

```bash
# Backend (порт 8001)
cd backend && uvicorn app.main:app --reload --port 8001

# Frontend (порт 3000)
cd frontend && nohup python3 -m http.server 3000 > /tmp/frontend.log 2>&1 &
lsof -ti:3000 | xargs kill -9  # остановить

# Переменные
DB_HOST=localhost  DB_PORT=5432  DB_NAME=realestate
DB_USER=postgres   DB_PASSWORD=...
```

### 8.2 Продакшн (docker-compose.prod.yml)

Три сервиса без Redis, без отдельного frontend-контейнера:

```yaml
services:
  db:       # postgres:16-alpine, volume postgres_data
  backend:  # build ./backend, port 8000 внутри, env_file .env.prod
  nginx:    # nginx:1.25-alpine, ports 80/443
            # ./frontend:/usr/share/nginx/html:ro
            # /api/ → proxy_pass backend:8000
```

Деплой:
```bash
docker compose -f docker-compose.prod.yml up -d
```

| Secret | Описание |

| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | Уведомления об ошибках парсеров |

## 11. Важные технические замечания

1. **ECharts** вместо Highcharts — бесплатная лицензия Apache 2.0. Подключать через CDN: `https://cdnjs.cloudflare.com/ajax/libs/echarts/5.4.3/echarts.min.js`

2. **API ЦБ РФ:** ипотечная статистика публикуется в виде Excel-файлов. Парсер скачивает файл со страницы cbr.ru/statistics/bank_sector/mortgage/

3. **fedstat.ru:** запускать скрипты только локально (облачные IP блокируются). Частота запросов: ≤1 req/sec.

4. **Временные зоны:** все даты хранить в UTC. Российские данные без явного TZ считать как MSK (UTC+3).

5. **NULL vs 0:** при отсутствии данных хранить NULL, не 0. На графике ECharts это отображается как разрыв линии (`connectNulls: false`).

6. **Ретроспективные правки:** Росстат и ЦБ периодически пересматривают данные. Парсеры делают UPSERT, не INSERT.

7. **period_type важен:** `period` — значение за промежуток (ипотека, ввод жилья). `point_in_time` — значение на дату (задолженность, строящееся жильё). YoY считается одинаково, но подписи на графике разные.

8. **periodicity='quarterly'** добавлено для 1.2 и 1.3 (помимо monthly/annual). Метки: «Q1 2024», «Q2 2024» и т.д.

9. **Порт backend:** локально 8001, в Docker 8000. Переменная `window.API_BASE = 'http://localhost:8001/api'` задаётся в каждом HTML-файле.

10. **CORS:** backend разрешает запросы с localhost:3000 и localhost:8080 (через config.py).
